# Facts added during review (2026-10-14)

These came in after the three research passes, from the review of [locked-devices.md](../../locked-devices.md). Each entry gives the page it was read from, how it was read, and the words that the page relies on. Nothing here was tested on a device.

How each page was read: "raw" means the text was read as it is published. A `*` means it came through a summarising tool, so read the page again before relying on it.

## Sending from a lock screen (section 5.2 of the page)

- [DOC, raw] Android `Notification.Action.Builder.setAuthenticationRequired(boolean)`, added in API level 31: "Sets whether the OS should only send this action's PendingIntent on an unlocked device. If this is true and the device is locked when the action is invoked, the OS will show the keyguard and require successful authentication before invoking the intent. If this is false and the device is locked, the OS will decide whether authentication should be required." https://developer.android.com/reference/android/app/Notification.Action.Builder
- [DOC, raw] Android `TileService.isLocked()`, added in API level 24: "Checks if the lock screen is showing. When a device is locked, then showDialog(Dialog) will not present a dialog, as it will be under the lock screen. If the behavior of the Tile is safe to do while locked, then the user should use ContextWrapper.startActivity(Intent) to launch an activity on top of the lock screen, otherwise the tile should use unlockAndRun(Runnable) to give the user their security challenge." And `unlockAndRun(Runnable)`: "Prompts the user to unlock the device before executing the Runnable. The user will be prompted for their current security method if applicable and if successful, runnable will be executed. The Runnable will not be executed if the user fails to unlock the device or cancels the operation." https://developer.android.com/reference/android/service/quicksettings/TileService
- [DOC, raw] iOS `UNNotificationActionOptions.authenticationRequired`: "The action can be performed only on an unlocked device." Discussion: "When the user selects an action with this option, the system prompts the user to unlock the device. After unlocking, the system notifies your app of the selected action." https://developer.apple.com/documentation/usernotifications/unnotificationactionoptions/authenticationrequired
- [DOC, raw] App Intents: for `AppIntent.authenticationPolicy`, "The default value of this property is IntentAuthenticationPolicy.alwaysAllowed, which allows the intent to run without authentication, including when the device is locked." `IntentAuthenticationPolicy.requiresLocalDeviceAuthentication` is "A policy that requires the person to unlock the device running the intent." https://developer.apple.com/documentation/appintents/appintent/authenticationpolicy and https://developer.apple.com/documentation/appintents/intentauthenticationpolicy
- [INFER] An iOS notification action that lacks the option can run while the device is locked. The documentation of the option implies it and nothing states it. I3 tests it.
- [UNKNOWN] Whether a control, a widget button or Siri that runs an App Intent honours the intent's authentication policy on a locked device. I5 tests it.

## Locking a Mac (section 5.6 of the page)

- [DOC, summary *] `pmset(1)`: "displaysleepnow - causes display to go to sleep immediately." The man page says "pmset must be run as root in order to modify any settings". That sentence concerns changing settings, and the entry for `displaysleepnow` does not mention root. Whether the call works without root is unknown (M12). Read on a third-party copy of the man page. https://www.sudo.is/docs/macos/man_pmset.html
- [DOC, summary *] Apple's help page for the Lock Screen settings names the setting "Require password after screen saver begins or display is turned off" and says "You can select the amount of time after the screen saver or sleep begins before a password is required." The page as read did not list the delay options. https://support.apple.com/guide/mac-help/change-lock-screen-settings-on-mac-mh11784/26/mac/26
- [INFER] With that setting at no delay, putting the display to sleep or starting the screen saver locks the Mac, and with a delay it does not. This was proposed in review and no source in the research says it. M12 tests it.
- [REPORT] The notification that would confirm the lock is `com.apple.screenIsLocked`. It is undocumented, and Chromium, Electron and Hammerspoon have used it (apple.md, and section 6 of the page).

## Sleep proxy outside Apple's devices (section 5.7 of the page)

- [REPORT, summary *] The documentation of Desomnia, a GPL-3 tool (the license shows only as a badge on its front page), lists "Windows 8 / 10 / 11, Linux, or macOS" as its system requirements. Its Sleep Proxy page says "Because it speaks the standard protocol, a Desomnia proxy can serve non-Desomnia clients", describes Desomnia as "the always-on device that accepts registrations and wakes hosts" and as "a machine that registers its own services before suspending", and says "the proxy sends a Magic Packet and the host comes back online". Its page on Apple's proxies says "A host with `handoff="SleepProxy"` registers with an Apple TV, HomePod or AirPort base station just as a Mac would" and "Apple proxies cap leases at 24 hours and always wake the host when the lease expires, regardless of any expiry setting." Only the documentation was read, and nothing can be taken from a GPL-3 project. https://desomnia.readthedocs.io/en/stable/ , https://desomnia.readthedocs.io/en/stable/modules/network/sleepproxy.html , https://desomnia.readthedocs.io/en/stable/modules/network/sleepproxy/apple.html
- [INFER] A Windows or Linux agent could register its service with a sleep proxy before the device sleeps, so that a paired device wakes it by connecting, and an awake Baton device could act as the proxy for its paired devices. It needs a network card that wakes on a magic packet and a proxy on the same link. W6 and L4 test the registration. Nothing here was run.
- The verdict in linux-android-tools.md that a sleep proxy is Apple-ecosystem only was too strong. A correction line is there.
